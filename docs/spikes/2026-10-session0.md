# Spike: can the engine run in session 0 (SYSTEM)?

Date: 29.10.2026, about 23:55 local, on `win-resolume` (SNV).

## Method

- Stopped the hand-started production MVP.
- Ran the same `wb2.exe` (`--sender "Arena - Screen 2" --dc GSM779465795 --seconds 15`) from a scheduled task as `SYSTEM` (`LogonType ServiceAccount`, `RunLevel Highest`).
- Restarted the production MVP 18 s later as PID 15624. The wall was dark about 19 s.

## Measured

- Log `C:\ProgramData\WallBridge\spike\session0.jsonl`:
  - `"senders":[]`: the `SpoutSenderNames` mapping is not visible from session 0.
  - Display.Core targets were listed, including `GSM779465795_0F_07DD_BC usage=2 connected=true`.
  - The log ends there: no `dc_open`, no `sender`. The task's last result was 1.
- The production MVP was back after the restart: `dc_open` 7680x1080@59.978, ~299 new / 10 s, 0 missed vblanks.

## Conclusion

Spout's shared-memory names (`SpoutSenderNames`, the per-sender 280 B mapping, `<name>_SpoutAccessMutex`) live in Arena's session namespace (session 1). A session 0 process cannot see them.

The engine therefore runs in the interactive session of `Resolume`, started by a logon scheduled task with restart on failure (the fohmixer / iemmixer pattern). `Resolume` logs on automatically (owner, 29.10.).
The updater stays a SYSTEM task.
